# CIDZO Task Dispatcher — GitHub-first policy

Founder expansion directive, 2026-11-26; proposed integration in #7/#8. No scheduler/service required. GitHub Issues are the coordination record, not a lock or independent authorization source. Founder-authorized #11/#12 may proceed before this documentation merges. Existing tasks retain explicit scopes; no retroactive blanket grants.

## Task record and lifecycle
Unique ID: CIDZO-<CENTER>-<sequence>; GitHub Issue number is canonical unique key for legacy tasks. Record sole owner, priority P0–P4, status, goal, full BASE SHA, explicit allowed write paths, read-only paths (default remaining repository, subject to access), forbidden paths (deny precedence), typed dependencies, architecture/contract references with SHA or accepted ADR, completion criteria, checks, PR links/HEAD and independent audit requirements. Record cross-scope exceptions with exact paths, sole writer, sequence, approver and reviewed refs. No GitHub account fabricated. Keep a small useful reserve only; avoid excess unfinished PRs. Queue: BACKLOG -> READY FOR ENGINEERING -> IN PROGRESS -> READY FOR AUDIT -> ACCEPTED FOR INTEGRATION REVIEW -> READY FOR FOUNDER MERGE -> INTEGRATED. BLOCKED or CHANGES REQUIRED returns to appropriate prior gate after resolution. IDLE when no authorized work. One bounded cycle per trigger.

## Dependencies
HARD: cannot begin specified work until verified prerequisite met. CONTRACT: may start after named stable interface accepted at exact revision, even before full implementation; fixtures/mock adapters explicitly non-production and excluded from release. SOFT: independent work may start; integration must check compatibility. Classify per task, not whole center. CTO records contract acceptance and exact base before activating. Recheck dependencies and actual files at every cycle; changed HEAD invalidates affected evidence.

## Single Writer per Scope
CTO owns governance/architecture; CHAT 03 shared frontend, design, templates and official site; CHAT 04 backend/data/API contracts and modules; CHAT 05 root package.json, pnpm-lock.yaml, workspace and shared TS/test config, workflows, Forge, security/quality; CHAT 07 only named showcases/<project>, docs/showcases/<project> and own handoff. CHAT 02 audits independently, no implementation; CHAT 06 manual Codex coordination only. Migrations assigned to one owner per change. Other paths read-only unless explicitly assigned; no changes to shared config by a consumer. Shared files and package-manifest/lockfile changes serialized by CTO; explicit dependencies or one designated writer. If overlap or changed SHA, stop and report BLOCKED, do not force push or overwrite. Check current Issue, main, own branch and full conflicting PR path lists before writing and before PR update. Issue comments are not atomic; conditional SHA update and branch protection remain required. No direct main writes or merge by centers.

## Scope verification (implementation #13)
Use simple base-controlled policy/checker, not a complex dispatcher. Exact issue binding and trusted authorization must not derive solely from mutable PR or Issue text; use reviewed base-controlled scope record or verified maintainer authorization tied to issue, paths and refs. Fail closed on missing/ambiguous authorization, changed refs, inaccessible or incomplete diff, unknown status. Inspect all changed files including deletes and both old/new rename paths, copy paths conservatively, exact directory boundaries and shared-file exceptions. No self-authorization by changing checker/policy within candidate PR. Use least-privilege trusted workflow, no untrusted code execution in privileged context, no secrets or unsafe interpolation. Test allow/deny, prefix collision, rename/delete, pagination, stale refs, missing task, shared ownership, self-authorization. Document bootstrap/checker updates and limits; founder alone may set required check after real verified CI exists. If reliable enforcement unavailable, report BLOCKED; manual checks continue, no pretend protection.
